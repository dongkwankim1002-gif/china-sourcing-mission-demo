# FC도착 — 디자인

> 선적 라벨과 부두의 언어. 짙은 남색 머리, 라벨 노랑 한 가지로 「지금 누를 것」을 가리키고,
> 나머지는 차가운 회색 종이 위에서 조용하고 촘촘하게.

frontend-design 스킬은 이 환경에 없었고(스킬·플러그인 검색 결과 없음), 같은 과정을 아래 기준으로 밟았다:
토큰 → 글꼴 → 크기 단계 → 와이어 → 「흔한 SaaS 템플릿처럼 보이는 곳」 자기 점검 → 캡처로 확인.

## 1. 색 토큰

핵심 여섯. 이름은 역할이다. 값은 `src/app/globals.css` 의 `:root` 한 곳에만 있다.

| 토큰 | 밝은 | 어두운 | 역할 |
|---|---|---|---|
| `--ink` 남색 | `#0E2340` | `#060D18` | 머리 띠, 강한 글자, 사이드바 선택 |
| `--label` 라벨 노랑 | `#F7C600` | `#FFD23F` | **주 행동 하나**, 강조, 초점 고리. 위 글자는 늘 남색 |
| `--ok` 청록 | `#0E7C71` | `#2BB3A3` | 정상·완료·확정 |
| `--stamp` 붉은 도장 | `#C0312A` | `#F0625A` | 예외·반려·만료 |
| `--caution` 호박 | `#9A5800` | `#F4A93B` | 주의·추가비용 가능·곧 만료 |
| `--paper` 종이 | `#EEF1F4` | `#0B1320` | 바탕. 크림·흙색 금지 |

보조(파생): `--surface #FFFFFF / #111B2B`, `--surface-2 #F6F8FA / #16223A`, `--line #D5DBE2 / #243247`,
`--text #0E1B2C / #E6ECF3`, `--muted #5B6878 / #93A1B3`.

- 상태색(청록·도장·호박)은 **아이콘 + 글자와 함께만** 쓴다. 색만으로 뜻을 싣지 않는다.
- 호박·청록을 글자에 쓸 때 밝은 모드는 4.5:1 을 넘는 어두운 단계(`#9A5800`, `#0E7C71`)를 쓴다.
- 노랑 위 글자는 남색(`#0E2340`, 대비 9.8:1). 흰 글자를 노랑 위에 올리지 않는다.

### 9구간 막대 색 — 순서형(ordinal) 한 색상 단계

구간은 **길의 순서**다(중국 → 한국). 순서를 바꾸면 뜻이 바뀌므로 범주형 9색이 아니라 남색 한 색상의
밝기 단계를 쓴다. `validate_palette.js --ordinal` 로 두 모드 모두 통과(인접 ΔL ≥ 0.06, 밝은 끝 2:1).

```
밝은 (#fff 위)  #001f51 #0e3163 #214375 #335587 #466899 #5a7bac #6d8ebf #82a2d2 #97b6e5
어두운 (#111b2b) #d8f0ff #c0dbfa #a8c6e9 #90b2d8 #799ec7 #638ab6 #4d77a6 #366495 #1f5185
               집하     창고작업 수출통관 국제운송 항만    관세사   국내창고 FC운송   회송대비
```

확정도는 색이 아니라 **무늬**로 싣는다(색각 이상·흑백 인쇄에서도 읽힌다):
확정 = 칠함 · 예상 = 45° 빗금 · 추가비용 가능 = 호박 점선 윤곽 · 참고치로 채움 = 속 빈 점선 · 제외 = 빈칸(회색 눈금만).
조각 사이 2px 종이색 틈. 마우스·손가락·키보드 초점을 대면 그 조각에 노랑 윤곽 + 값 풍선.

### 차트
- 한 차트 한 계열이 기본(지표 칸 추세선·일별 추이). 여러 계열이 필요하면 작은 그림 여러 개로 나눈다.
- 여러 계열을 꼭 겹칠 때는 dataviz 기본 범주 팔레트를 순서대로(1 파랑 `#2a78d6`, 2 주황 `#eb6834`).
- 열지도(구간 × 주)는 파랑 순차 단계(`#cde2fb` → `#0d366b`).
- 이중 축 없음. 격자는 1px 실선, 한 단계 옅게. 막대 두께 24px 이하, 끝 4px 둥글림.

## 2. 글꼴과 역할

| 글꼴 | 어디에 | 비고 |
|---|---|---|
| **Pretendard Variable** | 본문·UI 전부 | 저장소에 포함(`public/fonts/pretendard`, 동적 부분 집합 92조각). 숫자는 `tabular-nums` |
| **Black Han Sans** | 큰 숫자, 브랜드 글자, 공개 마켓 제목 | 저장소에 포함(`public/fonts/black-han-sans`). **업무 화면 본문에는 쓰지 않는다** |

중국어(간체) 화면은 Pretendard 가 한자를 다 갖지 않으므로 `"PingFang SC","Noto Sans SC","Microsoft YaHei"` 로 떨어진다.

> dataviz 지침은 「큰 숫자도 같은 산세리프」를 권하지만, 이 서비스는 큰 숫자를 Black Han Sans 로
> 한다(요청서가 정한 브랜드 결정). 대신 **한 화면에 하나**만, 업무 화면에서는 지표 칸 값에만 쓴다.

## 4. 간격·모서리·그림자

- 간격: 4 배수 — 2 · 4 · 8 · 12 · 16 · 24 · 32 · 48 · 64. 표 줄 높이 40(촘촘 36), 모바일 누름 영역 44 이상.
- 모서리: **2**(칩·라벨 조각) · **6**(버튼·입력) · **10**(패널). 알약(pill) 모양을 쓰지 않는다.
- 그림자: 0(기본 — 패널은 1px 선으로 선다) · 1 `0 1px 2px rgb(14 35 64 / .06)`(떠 있는 카드) ·
  2 `0 8px 24px rgb(14 35 64 / .14)`(팝오버·대화상자·명령 팔레트).
- 초점: 2px 라벨 노랑 고리 + 2px 남색 바깥 고리(두 모드 모두 보인다). `:focus-visible` 에만.
- 움직임: 120ms(색) · 200ms(위치). `prefers-reduced-motion` 이면 전부 0. 저절로 도는 장식 없음 —
  입력에 답하는 움직임(총액 숫자, 9구간 폭)만.

## 5. 이 서비스만의 한 가지 — 「9구간 막대」

집하 → 창고 작업 → 수출통관 → 국제운송 → 항만 → 관세사 → 국내 창고 → FC 운송 → 회송 대비를
**색 띠 하나**로. 폭 = 금액 비중, 무늬 = 확정도, 빈칸 = 업체가 맡지 않는 구간.
같은 컴포넌트(`<NineBar>`)가 네 곳에서 같은 모습으로 반복된다:

1. 공개 첫 화면 — 화물을 넣으면 폭이 움직인다(가장 크게, 구간 이름을 막대 아래 눈금으로).
2. 비교 목록 — 줄마다 얇은 막대(12px). 「9구간 표」 보기에선 막대 아래 숫자 표.
3. 견적 상세 — 응찰끼리 막대를 위아래로 쌓고 같은 척도(가장 큰 합계)로 그려, 길이로 합계를 비교한다(구간 경계는 금액에 따라 달라진다).
4. 청구 대조 — 응찰 막대 위에 청구 막대, 늘어난 구간에 도장 빨강 표시와 차액.

관세사 칸에는 늘 작은 「수수료 기준 제외」 표시가 붙는다(법적 선을 화면에서도 보인다).

## 7. 「흔한 SaaS 템플릿처럼 보이는 곳」 — 찾아서 고친 것

| 템플릿 냄새 | 고친 것 | 이유 |
|---|---|---|
| 그라데이션 첫 화면 + 가운데 큰 문구 + 버튼 둘 | 첫 화면 자체가 계산기. 문구는 왼쪽 한 줄, 총액이 주인공 | 이 서비스의 약속은 「같은 조건 총액」이다. 보여 주는 게 설명보다 빠르다 |
| 둥근 아이콘 원 + 기능 3칸 카드 | 없앴다. 그 자리에 9구간 설명 띠(번호 붙은 눈금) | 기능 목록은 누구나 쓴다. 9구간은 이 서비스만 그린다 |
| 보라/파랑 주 버튼 | 라벨 노랑 + 남색 글자, 한 화면에 주 행동 하나 | 선적 라벨의 노랑은 부두에서 「여기를 보라」는 뜻이다 |
| 알약 모양 배지 | 2px 모서리 라벨 조각 칩, 왼쪽 3px 색 띠 | 화물 라벨처럼 읽히고, 줄 높이가 흔들리지 않는다 |
| 어디나 부드러운 큰 그림자 카드 | 1px 선 패널, 그림자는 떠 있는 것(팝오버·대화상자)에만 | 업무 화면은 촘촘해야 하고, 그림자는 층을 뜻할 때만 쓴다 |
| 큰 색 아이콘이 붙은 지표 카드 | 아이콘 없는 지표 칸: 값 · 지난 기간 대비 · 추세선 | 아이콘은 정보가 없다. 추세선은 있다 |
| 회색 로고 벽 「함께하는 기업」 | 업체가 직접 올린 로고만, 없으면 이름 글자 마크 + 「공식 등록」 표시 | 가짜 신뢰 신호를 만들지 않는다 |
| 사진·별 다섯 개 후기 캐러셀 | 평가 기록에서 뽑은 문장 목록, 별점 대신 도장 모양 점수, 구간·품목 표기 | 저절로 도는 장식 금지. 후기는 검증 가능한 기록에서 |
| 알록달록 아이콘 사이드바 | 단색 선 아이콘, 선택은 남색 바탕 + 노랑 왼쪽 띠 | 조용하게 |
| 회전하는 원 로딩 | 레이아웃을 닮은 스켈레톤 | 기다리는 동안에도 자리가 보인다 |

## 8. 문구 원칙

- 사용자 말로: 「웹훅·레코드·엔티티·데이터 삽입」 금지 → 「기록」「요청」「업체」「올리기」.
- 버튼은 하는 일 그대로. 같은 행동은 끝까지 같은 이름 — `src/lib/terms.ts` 한 곳에 모은다.
  (예: 「견적 요청 올리기」「이대로 응찰」「예약으로 전환」「청구서 등록」「평가 남기기」「요금표 추가」)
- 숫자: 원화 천 단위 구분, 큰 금액은 「1,284만 원」「3.2억 원」 요약 + 원 단위 툴팁.
- 날짜: 「9월 25일(목)」, 올해가 아니면 「2025년 9월 25일」. 마감은 「마감까지 5시간」.
- 법적 선을 문구로: 「운송계약은 화주와 물류사가 직접 맺습니다」「관세·부가세는 참고 추정입니다」.
