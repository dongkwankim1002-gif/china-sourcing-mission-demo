# 유사상품 중국 소싱처 발굴 — 패밀리 확장 모듈 기획 (v2 3차 sourcing)

> 상태: **미리보기**(차후 개발 예정). 스위치 `sourcing.enabled` 기본 꺼짐 — 모든 화면에 「준비 중 · 미리보기」가 뜨고,
> 요청은 관심 등록처럼 **기록만** 한다. 외부 호출·메일·문자 발송은 없다. 이 문서는 법률·약관 자문이 아니다.
> 확인하지 못한 사실은 「확인 필요」로 적었다. 예시 이름(「예시 공장 A」 등)은 실제 회사가 아니다.

읽는 사람: 이 모듈을 켤지, 어떤 순서로 키울지 정할 사람(대표·운영 책임자·법무 검토 담당).
각 절 끝의 **정할 일**을 모아 12절에 다시 적었다.

---

## 1. 목적 — 왜 만드는가

FC도착은 「중국 공장 → 쿠팡 FC」 **물류비**를 9구간으로 표준화해 비교·확정하는 곳이다. 셀러가 실제로 돈을 버는 식은
`판매가 − 쿠팡 비용 − (상품 원가 + 물류비 + 관세)` 이고, 물류비는 그중 한 칸이다. 셀러 인터뷰(2차 interview)와 판매손익
계산기(1차 tools)에서 드러나듯, 마진을 가장 크게 흔드는 것은 **상품 원가(공장 단가)** 다.

이 모듈은 셀러가 **이미 잘 팔리는 자기 상품과 비슷한 상품을 더 싸게·더 안정적으로 만들어 줄 중국 공급처**를 찾게 돕는다.
찾은 뒤에는 도착원가·마진을 같은 엔진으로 계산하고, 샘플·검품·발주를 거쳐 **FC도착 물류 견적으로 곧장 넘긴다**.

- 셀러에게: 「이 상품, 다른 공장에서 받으면 개당 얼마 남나」를 한 화면에서 비교.
- FC도착에게: 발주가 생기는 순간이 물류 수요가 생기는 순간이다. 소싱 → 물류로 이어지는 입구가 하나 더 생긴다.
- 하지 않는 것(1단계): 플랫폼이 상품을 사서 되파는 것(직접 매입), 공급처와의 대금 중개·에스크로, 품질 보증.

## 2. 패밀리 사이트 개념

| 항목 | 제안 | 정할 일 |
|---|---|---|
| 이름·도메인 | **가칭** 「FC도착 패밀리 · 소싱」. 별도 브랜드·도메인을 쓸 수 있게 경로를 `/family/sourcing` 으로 따로 두었다(나중에 도메인만 연결). | 브랜드 이름·도메인·상표 출원 여부 — **사람이 정한다** |
| 계정 | **같은 로그인**(FC도착 계정·조직 그대로). 화주 조직의 사람만 소싱 요청을 남기고, 운영자(플랫폼 조직)가 대기열을 본다. 가입을 따로 받지 않는다. | 별도 도메인이면 로그인 쿠키를 어떻게 나눌지(같은 상위 도메인 / 별도 로그인 화면) |
| 원가 엔진 | **9구간 원가 엔진·구간 시세를 공유**한다. 후보 공급처의 도착원가는 FC도착의 `computeQuote`·`compare`(구간 시세) → `sellerPnl`(판매손익)로 계산한다 — 새 계산식을 만들지 않는다. | — |
| 자료 | 소싱 요청·후보·단가는 FC도착 DB 의 새 표 다섯(0018). 화주는 **자기 조직 것만**, 운영자는 전부 본다. | 패밀리 사이트를 다른 회사가 운영하게 되면 자료 분리(별도 DB) |
| FC도착과 오가는 길 | FC도착 머리·바닥글의 「패밀리 사이트」 → 소개 화면. 화주 메뉴 「소싱처 찾기(미리보기)」. 후보마다 「이 조건으로 물류 비교」 → FC도착 비교 화면(`/app/compare?…` 화물 조건 그대로). 소개 화면의 머리띠에 「FC도착으로 돌아가기」. | — |

화면 구분: 패밀리 화면은 FC도착의 남색 머리 대신 **종이색 머리 + 청록 띠**(역할 토큰 `--surface`·`--ok`)를 쓴다.
새 색을 만들지 않고 기존 역할 안에서 「다른 방」임을 보인다(DESIGN.md 1절).

## 3. 사용자 여정 — 단계별 화면과 자료

| # | 단계 | 화면(이번에 만든 것) | 자료 | 누가 |
|---|---|---|---|---|
| 1 | **잘 팔리는 내 상품 고르기** | `/app/sourcing` 「시작점」 — 저장한 SKU(1차) · 판매 분석 상품(3차 sales — 최근 30일 판매량 순) · 직접 입력 | `fcd.skus`(이름·HS 분류·목표 판매가·수량·무게·부피·물품가) · `fcd.v_sales_products_current`·`v_sales_orders_current`(함수 `salesProductsForSourcing()`) | 화주 |
| 2 | **유사상품 조건 적기** | 같은 화면 요청 폼 — 상품명·분류·사진 주소·목표 판매가·월 판매량·인증 필요 여부(+어떤 인증)·첫 발주 수량·선호 출발지·메모 | `sourcing_requests` 한 줄. 처리 기한 = 만든 날 + 설정 `sourcing.rules.slaDays` | 화주 |
| 3 | **후보 공급처 비교** | `/app/sourcing/[id]` 비교표 — 단가 구간·최소 주문량(MOQ)·생산 일수·공장/무역상 구분·평점·인증(주장/확인)·샘플비·유사도 | `sourcing_candidates`(담당이 넣음) + `candidate_quotes`(조건, 새 판) | 담당이 넣고 화주가 봄 |
| 4 | **도착원가·마진 시뮬** | 후보마다 개당 도착원가(상품+9구간 물류+관세 참고)·개당 마진·손익분기 판매가·발주 총이익. 수량·판매가를 바꿔 다시 셈 | 서버에서 `compare`(구간 시세 중간값, 업체 적으면 플랫폼 참고치) → `sellerPnl`. 대행 수수료(가정치)는 추가비용 칸 | 시스템 |
| 5 | **샘플·현지 검품** | 후보마다 「샘플 요청(관심 등록)」 — 스위치 꺼짐이면 기록만 | `sourcing_sample_interests` | 화주 → 담당 |
| 6 | **발주** | 이번엔 없음(안내만). 발주서·대금은 셀러와 공급처가 직접 | — | 화주·공급처 |
| 7 | **FC도착 물류 견적으로 넘기기** | 후보마다 「이 조건으로 물류 비교」 → `/app/compare?hub=…&units=…&kg=…&cbm=…&goods=…&cur=RMB` | 후보의 개당 무게·부피·박스 입수 × 수량 | 화주 |

상태(요청): `requested`(접수) → `researching`(조사 중, 담당 배정) → `candidates_ready`(후보 있음) → `sample_requested`(샘플 요청) → `closed`(끝) · `cancelled`(화주 취소).
상태 바뀜은 덧붙이는 기록(`sourcing_request_events`)으로 쌓는다 — 요청 줄을 고치지 않는다.

## 4. 자료원 갈래와 고른 이유

| 갈래 | 무엇 | 장점 | 막는 것 | 판단 |
|---|---|---|---|---|
| ① **공식 API·이미지 검색** — 1688 개방 플랫폼, Alibaba.com Open API, 타오바오 개방 플랫폼 | 키워드·이미지(1688 「拍立淘」 계열 以图搜款)로 후보를 자동으로 모은다 | 빠르고 넓다 | 개발자 등록·앱 종류(자용/제3자)·API 권한 신청·심사가 필요하다고 안내된다. 크로스보더(跨境) 솔루션은 ISV 신청 방식으로 보인다. **이용약관의 자료 재표시·저장·재판매 범위, 한국 법인의 신청 가능 여부, 비용은 확인 필요.** 이 환경에서 open.1688.com 은 접속이 막혀 원문을 못 읽었다 | 3단계(API 연동)로 미룬다. 코드는 제공자 인터페이스만 두었다 |
| ② **현지 소싱 담당 수동 조사** | 중국 현지(이우·광저우 등) 담당이 요청을 보고 공장·무역상을 찾아 조건을 받아 **운영 화면에 직접 넣는다** | 약관 문제 없음, 담당이 공장/무역상 여부·인증 서류를 직접 확인, 샘플·검품으로 이어짐 | 사람 손 — 요청당 시간(처리 기한), 담당 확보 | **1단계 권장.** 이번 구현의 운영 `/admin/sourcing` 이 이 길이다 |
| ③ **셀러가 링크 붙여넣기 → 담당 확인** | 셀러가 이미 본 1688·타오바오 상품 링크를 요청 메모/사진 주소로 남기면, 담당이 그 링크의 공급처를 확인해 후보로 넣는다(`source = seller_link`) | 셀러 의도가 분명, 자동 수집 없음 | 링크 속 자료를 **앱이 긁어 오지 않는다**(사람이 연다). 링크가 위조품일 수 있다 | ②와 같이 1단계에 둔다 |

코드: `src/lib/sourcing/providers` — `SourcingProvider` 인터페이스(`search(query) → 후보[]`) + **흉내 제공자 하나**
(`MockSourcingProvider`, 결정적 가짜 후보 「예시 공장 A」…). 공식 API 제공자는 만들지 않았다 — `getSourcingProvider('1688')`
등은 「계약·권한 확인 전 — 준비 중」 오류를 낸다. 흉내 제공자도 밖을 부르지 않는다(시험이 `fetch` 를 막고 확인한다).

## 5. 유사도 판단

순수 함수 `similarityScore()`(`src/lib/sourcing/similarity.ts`) — 0~100점과 까닭.

1. **낱말**: 요청 상품명·키워드와 후보 상품명을 낱말(띄어쓰기·기호로 가름) + 글자 두 개 묶음(한글·한자 붙여 쓴 말 대비)으로 나눠 겹침(Dice 계수)을 본다.
2. **분류**: 요청 분류(관세 분류 칸 `hs_category`)와 후보 분류가 같으면 만점, 다르면 0.
3. **가격대**: 후보 단가(원 환산)가 「기대 매입가 = 목표 판매가 × `targetCostShareBp`」의 ±`priceBandBp` 안이면 만점, 두 배 폭까지 줄어 0. 목표 판매가가 없으면 가격 항목을 빼고 나머지 비중으로 다시 나눈다.
4. 가중치·최소 표시 점수는 설정 `sourcing.rules.similarity`(첫 판 낱말 50% · 분류 20% · 가격 30%, 30점 미만은 「비슷하지 않음」).
5. **차후 이미지**: 사진 특징 비교는 ① API 또는 별도 이미지 모델이 필요하다. 인터페이스 자리(`imageBp`)만 두고 0으로 둔다.

유사도는 **정렬·참고용**이다. 「같은 상품」이라는 판정이 아니며, 지식재산 침해 여부 판단이 아니다(9절).

## 6. 운영 흐름 — 요청 대기열·담당 배정·처리 기한

```
화주 요청 ─▶ 대기열(/admin/sourcing) ─▶ 담당 배정·「조사 중」 ─▶ 후보 넣기(1~5곳) ─▶ 「후보 있음」
                 │ 처리 기한 = 접수 + slaDays(첫 판 5일)             │                        │
                 └ 기한 지나면 붉은 도장 「기한 지남」              └ 조건 바뀌면 새 판      └ 샘플 요청 ─▶ 담당 연락(앱 밖)
```

- 담당 배정은 상태 기록에 담당 이름(운영 조직 사람)을 함께 남긴다. 고치지 않고 새 기록.
- 후보 조건(단가 구간·MOQ·생산 일수·샘플비·개당 무게/부피)은 `candidate_quotes` 새 판으로만 바꾼다. 후보 내리기도 새 판(`status = withdrawn`).
- 흉내 제공자로 「예시 후보 채우기」 버튼(미리보기·교육용) — 넣은 후보는 `source = mock` 이고 화면에 「예시」가 붙는다.
- 한 조직이 동시에 열어 둘 수 있는 요청 수: 설정 `sourcing.rules.maxOpenPerOrg`(첫 판 10).
- 준비물(1단계 시범): 현지 담당 1명(중국어·한국어), 검품 체크리스트, 공급처 확인 서류 목록(영업집조·수출 실적·인증서 사본), 샘플 받는 주소, 응답 기한 규칙.

## 7. 수익 — 가정치

| 항목 | 첫 판 **가정치** (설정 `sourcing.fees`) | 근거 |
|---|---|---|
| 소싱 대행 수수료 | 발주 상품가의 5% | 업계 구매대행·소싱 대행 관행을 대략 본 **가정** — 확인 필요 |
| 샘플 처리 | 건당 30,000원(샘플비·국제 배송 별도) | 가정 |
| 현지 검품 | 1일 300,000원 | 가정 |

- 화면의 마진 시뮬은 「대행 수수료 포함(가정치)」로 계산해 보여 준다. 셀러가 내는 돈이 줄면 마진이 이만큼 는다는 뜻.
- 물류 수수료(FC도착 본업)는 기존 `commission_rate_bp` 그대로 — 소싱에서 이어진 선적도 같은 기준.
- 돈을 받는 흐름은 없다(스위치 꺼짐). 받게 되면 세금계산서·결제대행 계약이 먼저다.

## 8. 절차·준비물 — 1단계 시범을 켤 때

1. 법무 검토(9절 위험 넷) → 이용약관에 「소싱 대행」 조항, 개인정보 처리방침에 「요청 내용을 현지 담당에게 보여 줌」.
2. 현지 담당 계정을 운영 조직에 만든다(`platform_admin`). 담당만 후보를 넣는다.
3. 설정 `sourcing.rules`·`sourcing.fees` 를 사람이 정한 값으로 새 판.
4. `sourcing.enabled` 를 켠다 → 화면의 「준비 중 · 미리보기」가 「시범 운영」으로 바뀐다. **켜도 앱은 밖으로 연락하지 않는다** — 담당이 앱 밖(메신저·메일)에서 공급처와 연락한다.
5. 셀러 3~5곳으로 4주 시범 → 요청 수·기한 안 처리율·샘플 전환율·발주 전환율·물류 견적 전환율을 본다.

| 위험 | 무엇이 문제인가 | 이번 대응 | 사람이 정할 일 |
|---|---|---|---|
| **지식재산·위조품** | 「비슷한 상품」이 상표·디자인·특허를 침해할 수 있다. 관세법 제235조는 지식재산권 침해 물품의 수출입을 막고, 권리자가 세관에 신고·통관 보류를 요청할 수 있다(관세청 지식재산권 보호 안내). 통관 보류 = 물류비·일정 손실 | 유사도는 「같은 상품」 판정이 아니라고 화면에 적는다. 후보에 브랜드 로고·상표가 보이면 넣지 않는다(운영 규칙). 요청 폼에 「타사 상표·디자인을 베끼는 요청은 받지 않습니다」 | 운영 규칙 문안·거절 기준, 권리자 신고가 들어오면 후보를 내리는 절차 |
| **KC 인증** | 전기용품·생활용품은 「전기용품 및 생활용품 안전관리법」, 어린이제품은 「어린이제품 안전 특별법」에 따라 수입자가 통관 전 인증(안전인증·안전확인·공급자적합성확인)을 받아야 하는 품목이 있다. 어린이제품은 표시 없는 제품의 판매·구매대행도 금지된다고 안내된다 | 요청에 「인증 필요 여부」 칸, 후보의 인증은 **「주장」과 「담당 확인」을 나눠** 보인다. 중국 인증서(CCC 등)는 KC 가 아니라고 적는다 | 품목별 인증 판단은 시험·인증기관에 묻는다. 비용(시험비)을 시뮬에 넣을지 |
| **HS 분류·관세** | 분류가 바뀌면 관세율이 바뀌고 마진이 바뀐다. 시뮬은 FC도착 `fcd.duty_rates` 의 분류별 **참고 세율**만 쓴다 | 「관세·부가세는 참고 추정입니다」를 시뮬마다 붙인다. 분류는 요청의 분류를 그대로 쓴다 | 큰 발주는 관세사 확인·품목분류 사전심사(관세법 제86조, 원문 대조 필요) 안내 |
| **공급처 사기·품질** | 선금 뒤 잠적, 샘플과 다른 본품, 공장이라 했는데 무역상 | 공장/무역상 구분·운영 연수·평점은 **담당이 확인한 값만** 넣는다(흉내 후보는 「예시」). 대금 중개를 하지 않는다 | 공급처 확인 서류 목록, 검품 기준, 플랫폼 책임 범위(「소개·조사까지」) 약관 문구 |
| 개인정보 | 요청의 상품 사진 주소·메모가 현지 담당에게 보인다 | 연락처 칸이 없다. 사진은 주소(URL)만 — 파일을 받지 않는다 | 처리방침 개정 |
| 약관(API) | ①갈래 API 자료를 저장·재표시해도 되는지 | 쓰지 않는다(흉내만) | 1688·알리바바 약관 원문 검토 |

플랫폼 책임의 선(제안): **「후보 소개·조건 정리·도착원가 계산까지」**. 발주·대금·품질·인증 취득의 당사자는 셀러다. 화면 문구로도 보인다.

## 12. 사람이 정할 일

1. 패밀리 사이트 **이름·도메인**(지금 가칭), 별도 도메인이면 로그인 나누는 법.
2. **1단계 시범을 할지** — 현지 소싱 담당(누가, 몇 명, 어디), 처리 기한(5일이 맞는지).
3. **수수료 가정치** — 대행 5% · 샘플 30,000원 · 검품 1일 300,000원이 맞는지. 돈을 받는다면 결제·세금계산서.
4. **책임의 선** 약관 문구 — 「소개·조사까지, 발주·대금·품질은 셀러와 공급처」.
5. **지식재산 운영 규칙** — 거절 기준, 권리자 신고 시 후보 내리기.
6. **KC 인증** — 인증 필요 품목의 안내 문구, 시험비를 시뮬에 넣을지.
7. **공식 API(3단계)** — 1688·알리바바·타오바오 약관 원문 검토(저장·재표시·재판매), 한국 법인 신청 가능 여부, 비용.
8. 개인정보 처리방침 개정(요청 내용을 현지 담당에게 보임).
9. `sourcing.enabled` 를 켤 때 — 1~5·8 이 끝난 뒤.
