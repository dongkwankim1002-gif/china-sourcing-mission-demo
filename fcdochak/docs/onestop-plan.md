# 원스톱 대행형 구역 `/onestop` — 기획 (v2 4차 · 미리보기)

> 이 문서는 사람이 읽고 결정하도록 쓴 것이다. 숫자(요금·일수)는 모두 **가정치**이고, 법·약관 사실에는 출처를 달았다.
> 원문을 직접 확인하지 못한 것은 「확인 필요」로 적었다. 법률 자문이 아니다.
> 스위치 `onestop.enabled` 는 **꺼짐**으로 시작한다 — 꺼져 있으면 주문서는 「접수 기록만 · 대행 계약 전」이고 결제·발송·대행 계약은 없다.

## 1. 목적 — 무엇을 견주려는가

v2 의 가설(방안 A)은 「셀러는 **비교**보다 **확정된 도착 원가와 책임**을 원한다」다. 비교 화면·확정가·회송 보장·제휴 주선사가 그 가설의 판이다.

원스톱 판(방안 E 쪽)의 가설은 다르다:

> **소량·처음·사입 대행이 필요한 셀러는 비교하고 싶지 않다. 가격 하나를 보고 맡기면 끝나기를 원한다.**

두 가설은 같은 셀러에게 서로 다른 첫 화면을 준다. 그래서 v2 안에 구역을 따로 두고(홈·메뉴·흐름이 v2 화면과 섞이지 않게), 9구간 원가 엔진·로그인·DB·데모·선적 단계·서류함은 함께 쓴다. 비교실(`/lab`)에서는 v2 주소의 `/onestop` 을 「원스톱」 판으로 연다.

- **이기면**: `/onestop` 을 소량 셀러의 홈으로 올린다(홈 첫 화면에서 「맡기기」와 「비교하기」 두 갈래) → 사람이 정할 일(8절)의 계약·결제·운영 준비를 시작한다.
- **지면**: 구역을 걷어낸다(표 두 개와 화면 폴더 하나 — 11절의 걷어내기 순서). v2 의 확정·책임 판에 집중한다.

## 2. 대상 셀러와 약속하는 가치

| 대상 | 특징 | 지금 겪는 일(가설) |
|---|---|---|
| 소량 셀러 | 한 번에 0.3~3 CBM, 상품 1~5종 | 포워더가 최소 운임을 붙여 개당 물류비가 튀고, 견적 비교가 번거롭다 |
| 처음 수입하는 셀러 | 9구간·통관·FC 입고 규격을 모른다 | 무엇을 물어야 할지 몰라 견적서를 읽지 못한다 |
| 사입 대행이 필요한 셀러 | 1688·도매시장 상품을 직접 사서 모으기 어렵다 | 공장마다 따로 창고로 보내고, 대금·검품·바코드를 여러 곳에 맡긴다 |

**약속하는 가치 두 가지 (화면 문구도 이 둘만)**
1. **가격 하나** — 공동 혼적 CBM당 요금 + 개당 작업비·바코드·검품, 최소 요금. 9구간을 셀러가 고르지 않는다. 관세·부가세만 실비(참고 추정 표시).
2. **맡기면 끝** — 사입처 링크·수량만 적으면 대금 확인 → 공장 입고 → 검품 → 바코드 → 혼적 출항 → 통관 → FC 입고를 한 타임라인에서 본다.

비교·등급·응찰은 원스톱 화면에 보이지 않는다. 대신 「9구간 참고치와 얼마 차이」 한 줄만 보여 준다(투명성은 남기되 고르게 하지 않는다).

## 3. 갈래와 고른 것

| 갈래 | 내용 | 장점 | 단점 | 고름 |
|---|---|---|---|---|
| ① 별도 사이트 | 도메인·로그인·DB 따로 | 브랜드가 깔끔 | 엔진·자료를 두 벌 관리, 견주기 어렵다 | ✕ |
| ② v2 안의 구역 `/onestop` | 자체 머리·메뉴·바닥, 엔진·계정·DB 공유 | 같은 셀러·같은 자료로 견줄 수 있다, 지면 폴더만 걷어낸다 | v2 와 헷갈릴 수 있다 → 머리에 「원스톱 · 미리보기」 | **○** |
| ③ v2 화면에 「맡기기」 버튼 섞기 | 홈·계산기·비교에 버튼 추가 | 만들기 쉽다 | 두 가설이 섞여 무엇이 이겼는지 모른다 | ✕ |

v2 와 닿는 곳은 딱 세 곳으로 줄였다: 공개 머리·바닥의 「원스톱」 링크 하나, 화주 대시보드(`/app`)의 원스톱 주문 카드, 운영 메뉴의 「원스톱 주문」.

## 4. 흐름 (셀러 쪽)

```
/onestop 홈 ─ 「맡기기」 하나(상품·수량·박스·CBM → 가격 하나 미리보기)
   │
   ├─ /onestop/price 요금표(공개) — 허브·방식별 CBM당, 개당 작업비·바코드·검품, 최소 요금, 혼적 마감 요일
   │
   └─ /onestop/order 주문서(로그인 화주)
         사입처 링크(선택) · 상품명·분류 · 수량·박스·CBM·무게 · 개당 매입가(사입 대행이면)
         · 허브·방식·도착 FC · 사입 대행 / 바코드 / 검품 수준
         → 가격 하나 + 9구간 참고치와의 차이 + 개당 도착원가(관부가세 참고 포함)
         → 「맡기기」 = 접수 기록(스위치 꺼짐: 「접수 기록만 · 대행 계약 전」)
   │
   └─ /onestop/orders · /onestop/orders/[id] 주문 목록·타임라인
         접수 → 사입 대금 확인 → 공장 입고 → 검품 → 바코드 → 혼적 출항 → 통관 → FC 입고
         (운영이 선적 기록을 이으면 출항·통관·FC 입고는 선적 9단계에서 따라온다 · 서류는 그 선적의 서류함)
```

**셀러 준비물** — 사입처 링크 또는 공장 연락(대행 안 할 때), 상품명·분류(관세율), 수량·박스 수·대략의 CBM·무게, 쿠팡 로켓그로스 입고 요청과 바코드(셀러가 WING 에서 만든다 — 바코드 부착만 대행), 수입자 명의 정보(사업자등록번호·통관고유부호 — **실제 운영 때 필요, 지금은 받지 않는다**).

## 5. 요금 구조 (가정치 — `fcd.settings` `onestop.tariff`)

값은 코드에 두지 않고 설정 한 곳에 둔다(어드민 설정 화면에서 새 판). 첫 판은 **가정치**(`example: true`)다.

| 항목 | 첫 판 가정치 | 근거(가정) |
|---|---|---|
| 공동 혼적 CBM당 — 이우 LCL(인천) | 219,000원 | 9구간 참고치(3 CBM·40박스 기준 약 70.6만 원 ≒ CBM당 23.5만 원)에서 혼적 규모 효과 −7% |
| 청도 LCL(인천) | 199,000원 | 산둥 쪽이 가깝다 |
| 청도 카페리(평택) | 239,000원 | 빠른 대신 비싸다 |
| 위해 카페리(인천) | 229,000원 | |
| 광저우 LCL(인천) | 239,000원 | 먼 허브 |
| 청구 CBM | 0.1 CBM 올림 | |
| 원거리 FC 할증(대구·창원·광주) | CBM당 30,000원 | FC 운송 거리 |
| 개당 작업비(입고·분류·재포장) | 60원 | |
| 바코드 부착 | 개당 90원 | 셀러가 준 쿠팡 바코드를 붙인다 |
| 검품 — 기본(수량·외관) / 정밀(작동·치수) | 개당 120원 / 350원 | |
| 사입 대행 수수료 | 물품가의 5% | 대금 확인·공장 연락·입고 확인 |
| 최소 요금 | 150,000원 | 소량 한 건의 고정 작업(서류·통관·FC 예약) |
| 혼적 마감 | 매주 화·금 17시(한국 시각) | 마감 뒤 접수는 다음 회차 |

계산 순서(순수 함수 `src/lib/money/onestop.ts`, 시험 `tests/v2-onestop.test.ts`):
1. 청구 CBM = 신고 CBM 을 0.1 올림. 혼적 운임 = 청구 CBM × CBM당(허브·방식). 원거리 FC 면 할증.
2. 개당 작업비·바코드·검품 = 수량 × 단가. 사입 대행이면 물품가(원) × 5%.
3. 합계 < 최소 요금이면 최소 요금(「최소 요금 적용」 표시).
4. **9구간 참고치와의 차이** = 원스톱 합계 − 같은 화물의 9구간 합계(구간 시세가 있으면 중간값, 없으면 플랫폼 참고치). 혼적 운임만의 차이도 따로.
5. **개당 도착원가** = (물품가 + 원스톱 합계 + 관세 참고 추정) ÷ 수량 — 부가세는 매입세액 공제 대상이라 빼고(판매손익 계산기와 같은 기준), 통관 때 먼저 낼 부가세 포함 값도 함께 보인다. 관부가세는 과세가격(물품가 + 도착항까지 운임 참고 + 보험)으로 추정 — 기존 `estimateDutyVat` 를 그대로 쓴다.

> **주의(가정치의 효과)**: 9구간 참고치는 구간마다 최소 요금이 붙어 소량일수록 비싸다(예: 0.8 CBM·300개 → 참고치 39.4만 원, 원스톱 25.6만 원, −35%). 원스톱이 소량에서 싸 보이는 것은 **혼적 CBM당 요금이 실제로 이 값에 나올 때만** 참이다 — 콘솔사 단가 확인(8절 4)이 이 가설의 핵심 전제다.

원 단위 계산은 정수(BigInt) 한 번 반올림. 요금표 화면·주문서·운영 화면이 같은 함수를 쓴다.

## 6. 운영 (사람이 하는 일 — 지금은 기록만)

| 단계 | 누가 | 무엇을 확인 | 기록 |
|---|---|---|---|
| 접수 | 셀러 | 주문서 | `onestop_orders` 첫 판 |
| 사입 대금 확인 | 운영 | 셀러가 보낸 대금·공장 결제(대행일 때) · 대행 아니면 공장 출고 확인 | 이벤트 `payment_confirmed` |
| 공장 입고 | 중국 창고 | 박스 수·실측 CBM·무게 | 이벤트 `factory_received` + (다르면) 주문 새 판(실측값·다시 셈) |
| 검품 | 중국 창고 | 수량·외관(정밀이면 작동·치수) · 불량은 사진 | 이벤트 `inspected` · 문제는 `issue` |
| 바코드 | 중국 창고 | 셀러 바코드 부착·스캔 시험 | 이벤트 `barcoded` |
| 혼적 출항 | 운영 | 마감 요일 회차에 실음 | 이벤트 `departed` 또는 선적 기록 잇기(주문 새 판 `shipment_id`) |
| 통관 | 관세사 | 수입신고(수입자 = 셀러) | 이벤트 `customs_cleared` 또는 선적 7단계 |
| FC 입고 | 국내 창고·운송 | 쿠팡 입고 요청 번호와 맞춤 | 이벤트 `fc_received` 또는 선적 9단계 |

- 단계는 **앞으로만** 간다(건너뛰기는 된다 — 예: 바코드를 안 맡기면 검품 다음 출항). 되돌리기는 없다 — 잘못 남기면 `issue` 로 설명을 남긴다. DB 가 막는다.
- 주문 내용이 바뀌면(실측 CBM·선적 잇기) 기존 줄을 고치지 않고 **새 판**(`supersedes_id`)을 쌓는다. 셀러는 첫 판만 만들고, 새 판은 운영만.
- 셀러는 접수 단계에서만 취소할 수 있다(대금 확인 뒤 취소는 운영과 이야기 — 환불 규칙은 사람이 정할 일).
- **선적 기록과 잇기**: 운영이 주문 새 판에 그 셀러의 선적 번호를 적으면, 출항·통관·FC 입고는 선적 9단계(`fcd.shipments.stage`)에서 따라온다(선적 5단계 → 혼적 출항, 7 → 통관, 9 → FC 입고). 서류(인보이스·패킹리스트·바코드 PDF)는 그 선적의 서류함에 있다.
  - 한계: 지금 선적 표는 **화주 한 곳** 기준이다. 실제 공동 혼적은 한 컨테이너에 여러 셀러가 탄다 → 운영 전에 「혼적 회차(여러 주문) ↔ 선적」 모델이 필요하다(사람이 정할 일 7).
- 혼적 마감: 주문서에 「다음 마감 ○월 ○일(화) 17시」를 보여 준다. 운영 대기열은 다음 마감 회차별로 볼 수 있게 가까운 마감 날짜를 함께 적는다.

## 7. 책임과 위험 — 대행 계약·결제는 사람이 정할 일

| 위험 | 무엇이 문제인가 | 지금 판의 처리 | 켜기 전에 정할 것 |
|---|---|---|---|
| **사입 대금 보관** | 셀러 돈을 받아 공장에 대신 내면 「남의 돈을 맡는」 구조다. 통신판매·구매대행이면 결제대금예치(에스크로) 또는 소비자피해보상보험 계약 의무가 걸릴 수 있다(전자상거래법 제13조 제2항 제10호·제24조 — 사업자 간 거래(B2B)에도 걸리는지 **확인 필요**) · 선불 충전식으로 받으면 전자금융거래법 선불전자지급수단 등록 대상인지 **확인 필요** | 대금을 받지 않는다. 「사입 대금 확인」은 운영이 확인했다는 기록뿐 | 결제대행(PG)·에스크로 제휴, 대금 흐름(셀러 → 에스크로 → 공장), 환불 규칙 |
| **분실·파손** | 공장 → 중국 창고 → 혼적 → FC 사이 어디서든 | 이벤트 `issue` 로 기록만. 보상 없음 | 적하보험 가입(누가·얼마), 보상 한도(개당·건당), 검품 전 파손은 공장 책임 |
| **통관 책임** | 수입신고의 수입자(화주)가 세액·원산지·인증 책임을 진다(관세법 제241조 수입신고 — **원문 대조 필요**) · KC 인증 품목·지식재산 침해(관세법 제235조)는 통관 보류 | 주문서에 「수입자는 셀러 본인 — 인증·표시는 셀러 책임」을 적는다(안내만) | 수입자 명의(셀러 명의 신고 vs 대행사 명의), 관세사 제휴, 통관 보류 비용 부담 |
| **운송 주선 등록** | 셀러에게 국제 운송을 자기 이름으로 떠맡고 운임을 받으면 국제물류주선업 등록(물류정책기본법 제43조, 법인 자본금 3억 원 이상·보증보험)이 필요하다 — `docs/alliance-plan.md` 1절과 같은 근거 | 요금표는 「가정치 · 대행 계약 전」, 계약 없음 | 제휴 주선사 명의로 계약할지(v2 alliance 구조 재사용) 직접 등록할지 |
| **가격 하나의 손실** | 고정 CBM당 요금보다 실제 원가가 오르면 플랫폼이 떠안는다(확정가와 같은 위험) | 9구간 참고치와의 차이를 운영 화면에 늘 보인다 | 요금표를 얼마나 자주 새 판으로 바꿀지, 손실 상한 |
| **쿠팡 입고 반려(회송)** | 바코드·포장 기준 위반이면 회송될 수 있다(제3자 안내 글 기준 — 쿠팡 WING 공식 입고 가이드 **확인 필요**) | 바코드는 셀러가 준 것을 붙이기만 | 회송 비용 부담, 재작업 요금 |
| **개인정보** | 사입처 링크·주소·연락처 | 연락처는 받지 않는다 | 처리방침 개정(중국 창고에 보이는 정보) |

## 8. 사람이 정할 일

1. **이 가설을 시험할지** — 비교실·인터뷰로 견준 뒤(9절) 이기면 켜기 준비, 지면 걷어내기.
2. **대행 계약 구조** — 누가 셀러와 계약하나(플랫폼 / 제휴 주선사 / 중국 현지 창고사) · 계약서(대행 범위·책임 한도·환불).
3. **사입 대금** — 받을지·어떻게(PG·에스크로·선불 충전), 전자상거래법·전자금융거래법 검토(7절 확인 필요 둘).
4. **요금표 첫 판** — 5절의 가정치(CBM당·개당·최소 요금·마감 요일)를 콘솔사 실제 단가로 바꿈. 바꾸면 `onestop.tariff` 새 판(`example: false`, 확인일).
5. **중국 창고·검품 파트너** — 어디(이우·청도), 검품 기준서, 불량 처리.
6. **보험·보상** — 적하보험, 분실·파손 보상 한도.
7. **혼적 회차 모델** — 여러 셀러 주문 ↔ 한 선적(지금은 화주 하나 선적과만 잇는다).
8. **수입자 명의·관세사** — 셀러 명의 신고를 기본으로 할지.
9. **`onestop.enabled` 켜기** — 2~8 이 끝난 뒤. 켜도 앱은 결제·메일·문자를 보내지 않는다(결제 연동은 따로 만든다).

## 9. v2 와 무엇을 어떻게 견줄까

| 방법 | 무엇을 본다 | 어디서 |
|---|---|---|
| **셀러 인터뷰** | 이미 있는 질문 「원스톱 배대지(구매부터 FC 입고까지 한 곳)를 써 보셨나요?」 + 원스톱 홈을 보여 주고 「이 가격 하나로 맡기겠다 / 비교하겠다」 · 확정가 지불 의향과 원스톱 요금 수용을 같은 셀러에게 | `/admin/research` 결정 보드(2차 interview) — 원스톱 화면 반응은 「화면 반응」 인용으로 모은다 |
| **비교실** | 같은 사람이 v2 홈과 원스톱 홈을 나란히 보고 평가 노트(첫 행동까지 걸린 시간·헷갈린 곳) | `/lab` 의 「원스톱」 판(v2 주소의 `/onestop`) |
| **지표** | 원스톱: 요금표 → 주문서 → 접수 전환, 접수 → FC 입고 일수, 주문당 CBM, 최소 요금 적용 비율, 9구간 참고치 대비 차이 · v2: 견적 요청 → 선택 → 선적 전환(`/admin/metrics`) | `/admin/onestop` 위 요약 칸 + `/admin/metrics` |

**판정선(제안 — 사람이 정한다)**: 인터뷰 20명 중 소량(3 CBM 이하) 셀러의 절반 넘게 「가격 하나로 맡기겠다」를 고르고, 원스톱 요금이 9구간 참고치보다 15% 이내로 비싸도 받아들이면 「원스톱 이김」. 절반 미만이거나 확정가 지불 의향(+3%)이 더 많으면 「v2 이김」.

- **이기면**: ① 홈 첫 화면에 「맡기기(소량)」 갈래를 올림 ② 8절 2~8 진행 ③ 혼적 회차 모델·결제 연동 설계.
- **지면**: ① 공개 머리·바닥의 링크와 대시보드 카드를 먼저 내림 ② 새 주문 받기를 멈추고(스위치 꺼짐 그대로) ③ 표 두 개는 지우는 SQL 을 사람이 만들어 실행(자동 삭제 없음) ④ `/onestop` 폴더 삭제.
- 어느 쪽이든 9구간 엔진은 남는다(원스톱 요금표를 만드는 데 쓴 참고치 비교는 확정가 판에도 쓸모가 있다).

## 10. 만든 것(코드)과 스위치

- 표(`0020_onestop.sql`): `fcd.onestop_orders`(접수 기록, 새 판 — 첫 판은 셀러, 뒤 판은 운영) · `fcd.onestop_order_events`(단계, 쌓기만, 앞으로만). RLS: 화주 본인 조직, 운영 전부. 어떤 표에도 UPDATE·DELETE 권한이 없다. 스위치가 꺼져 있으면 `preview = true` 주문만 넣을 수 있다.
- 설정: `onestop.enabled`(false) · `onestop.tariff`(가정치). 어드민 설정 화면에서 새 판.
- 계산: `src/lib/money/onestop.ts`(견적·최소 요금·9구간 차이·개당 도착원가) · 마감 요일·단계는 `src/lib/onestop/settings.ts`.
- 화면: `/onestop`(홈, 공개) · `/onestop/price`(요금표, 공개) · `/onestop/order`(주문서, 로그인 화주) · `/onestop/orders`·`/onestop/orders/[id]`(목록·타임라인) · `/app` 원스톱 카드 · `/admin/onestop`(대기열·단계 갱신·새 판).
- 데모: 데모 화주 주문 셋(접수 · 검품 · 선적과 이은 것) + 다른 데모 화주 하나. 모두 `is_demo` 조직 아래 — 걷어내기에 함께 사라진다.
- 결제·발송·대행 계약 없음. 밖으로 나가는 호출 없음.
