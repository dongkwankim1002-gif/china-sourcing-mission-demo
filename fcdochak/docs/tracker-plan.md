# 통관·입고 알리미 `/track` — 기획 (v2 5차 tracker)

> 사람이 읽고 결정하도록 쓴 문서다. 법·약관·API 사실에는 출처를 달았고, 원문을 직접 열어 보지 못한 것은 **「확인 필요」**로 적었다. 법률 자문이 아니다.
> 실제 관세청 호출은 서버 환경변수 `UNIPASS_ENABLED` 가 **꺼짐**(기본)이면 한 번도 일어나지 않는다. 이 작업 중에도 관세청을 부르지 않았다.
> 발송(메일·문자·카톡)은 없다. 알림은 화면 안 알림 센터에만 쌓인다(`OUTBOUND_ENABLED` 꺼짐 그대로).

## 1. 목적

### 1-1. 셀러에게 — 「지금 어디, 언제 FC」
중국에서 쿠팡 FC 로 들여오는 셀러가 가장 자주 묻는 말은 두 가지다.
1. **지금 어디 있나** — 입항했나, 보세창고에 들어갔나, 수입신고가 수리됐나, 반출됐나.
2. **언제 FC 에 들어가나** — 쿠팡 입고 예약(입고 예정일)을 잡고 재고 품절을 막으려면 날짜가 필요하다.

물류사에게 카톡으로 묻고 기다리는 대신, B/L 번호 하나로 관세청 공공 자료의 단계를 보여 주고, 같은 항구·같은 방식으로 **실제 걸린 날(실측)** 에서 셈한 예상일을 「보통 X일 · 늦으면 Y일」로 준다.

### 1-2. 플랫폼에게 — 거래 밖에서도 실측 자료가 생긴다 (분석의 모순 ③)
2026-09-25 전수 분석의 구조적 모순 ③은 「추천 점수에 넣을 **실측 자료를 얻을 방법이 없다** — 거래가 플랫폼 밖에서 끝나면 입항·통관·입고 시각을 모른다」였다.
알리미는 이것을 푼다.
- 셀러가 B/L 만 넣으면(거래가 FC도착 밖이어도) 관세청 단계 시각이 쌓인다.
- 번호를 FC도착 선적이나 물류사·관세사와 이으면 **물류사·관세사·항구·방식별 소요시간 분포**가 생긴다.
- 이 분포가 업체 화면의 「실측 통관 소요(표본 N)」, 예상일 엔진, 나중에는 추천 점수·「도착일 약속」의 근거가 된다.

### 1-3. 넣지 않는 것
개인 직구용 기능(면세 한도·합산과세·EMS·해외 쇼핑몰 제휴·개인통관고유부호 조회)은 넣지 않는다. 대상은 **B2B 일반 수입신고(LCL·FCL·항공·카페리) + 쿠팡 FC 입고**다.
참고한 다른 조회 서비스(지시문에 이름이 적힌 통관 알림 서비스 — 주소는 적지 않았다)는 **가치의 모양만** 참고했다 — 화면·문구·이름·자료를 긁거나 베끼지 않는다.

### 3-1. 단계 정규화
관세청 처리구분(`cargTrcnRelaBsopTpcd`) 원문은 그대로 남기고, 셀러가 읽는 아홉 단계로 접는다(`src/lib/unipass/stages.ts`, 순수 함수 + 시험).

| # | 단계 | 무엇에서 | 원문 낱말(가정 · 확인 필요) |
|---|---|---|---|
| 1 | 적하목록 제출 | 관세청 | 「적하목록」「적재화물목록」 |
| 2 | 입항 | 관세청 | 「입항」(입항보고 수리 등) |
| 3 | 하선 | 관세청 | 「하선」「하기」 |
| 4 | 보세구역 반입 | 관세청 | 「반입」 |
| 5 | 수입신고 | 관세청 | 「수입신고」(수리 전) |
| 6 | 수리 | 관세청 | 「수리」(수입신고수리) |
| 7 | 반출 | 관세청 | 「반출」 |
| 8 | 국내 운송 | 이은 선적(8단계 국내 창고) | — |
| 9 | FC 입고 | 이은 선적(9단계) 또는 쿠팡 WING 입고 기록 | — |

「보세운송」이 들어간 처리구분(보세운송 신고수리·반출 등)은 단계로 세지 않는다(보세구역 사이 옮기기 — LCL 이 CFS → 내륙 창고로 갈 때). 「반출」은 수입신고나 수리 **뒤에** 온 것만 반출로 센다(신고 전 반출로 폴링이 멈추거나 통관 소요가 짧게 잡히지 않게). 낱말 규칙은 원문 목록을 확인하지 못해 **가정**이다. 모르는 처리구분은 단계 없이 「원문 그대로」 타임라인에만 보인다. 규칙을 고치면 이미 쌓인 원문으로 다시 접을 수 있다(원문을 버리지 않는 이유).

## 4. 예상일 엔진

- **키**: (물류사, 관세사, 항구, 방식). 표본이 모자라면 (물류사, 항구, 방식) → (항구, 방식) → 설정의 가정치 순으로 물러난다. 화면에 어느 판으로 셈했는지(「이 물류사 실측 · 표본 N」「같은 항구·방식 실측」「가정치」) 적는다.
- **구간 둘**: ① 입항 → 수리(영업일) ② 수리 → FC 입고(영업일).
- **값**: 최근 N일(`tracker.rules.windowDays`, 첫 판 90일)의 중앙값(p50)과 90% 지점(p90). 분위수는 선형 보간(엑셀 PERCENTILE.INC 와 같은 방식). 「보통 X일」 = p50 반올림, 「늦으면 Y일」 = p90 올림.
- **달력**: 한국 영업일 — 토·일·공휴일·대체공휴일을 뺀다. 공휴일 목록은 `fcd.settings` `calendar.kr_holidays`(첫 판 2026~2027, **확인 필요** 표시 — 「관공서의 공휴일에 관한 규정」과 한국천문연구원 월력요항으로 운영자가 확인해 새 판으로). 제헌절(7월 17일) 공휴일 재지정 여부 등 확인하지 못한 날은 목록에 `confirmed: false` 로 두고 화면에 「확인 필요」.
- **같은 날 입항분 완료율**: 같은 항구·방식에 같은 날 입항한 화물 중 지금까지 수리된 비율. 표본 기준 미만이면 숨긴다.
- **계산 결과는 새 판**: `lead_time_stats` 에 계산할 때마다 새 줄(앞 판을 `supersedes_id` 로 가리킴). 운영 화면의 「통계 다시 셈」 또는 폴링 뒤.
- **표본 기준**: `tracker.rules.minSamples`(첫 판 5) 미만이면 공개 화면·업체 화면에 싣지 않는다(한 셀러의 화물이 드러나지 않게).
- **섞지 않기**: 예시(데모) 자료로 셈한 통계와 실제 자료로 셈한 통계는 따로 셈한다. 실제 통계는 관세청에서 온 기록(`source = 'unipass'`)만 쓴다(흉내·수기 입력은 제외).

## 5. 절차 · 준비물

### 5-1. 셀러
1. `/track` 에서 번호 종류(화물관리번호 / M B/L / H B/L)를 고르고 번호를 넣는다. B/L 이면 연도도.
2. 로그인하지 않으면 **결과만 보고 아무것도 저장하지 않는다**(IP 당 분당 횟수 제한 `tracker.rules.publicPerMinute`).
3. 화주로 로그인하면 「내 목록에 저장」 → `/app/tracking` 에서 알림 켜기·FC도착 선적과 잇기·물류사/관세사 고르기.
4. 선적과 이으면 그 선적 화면의 9단계 중 **한국 도착·수입통관**이 관세청 실측 시각과 함께 보인다(물류사 기록과 나란히).

### 5-2. 운영(켜기 전 준비물)
1. UNI-PASS 회원 가입(법인), API001 인증키 신청 — **3절 원문 확인 필요**.
2. 호출 한도·IP 제한·이용약관(제3자 제공·재가공·상업 이용) 확인.
3. Vercel 서버 환경변수: `UNIPASS_API_KEY`(값은 Vercel 에만), `CRON_SECRET`(무작위 32자 이상), 확인이 끝나면 `UNIPASS_ENABLED=on`.
4. 예약 작업(크론)은 **넣지 않았다**. 켜기로 정하면 `vercel.json` 에 아래를 더한다(사람이 정할 일):
   ```json
   { "crons": [{ "path": "/api/cron/unipass", "schedule": "*/30 * * * *" }] }
   ```
   Vercel 은 `CRON_SECRET` 이 있으면 `Authorization: Bearer <값>` 머리글을 붙여 부른다(Vercel 문서 「Securing cron jobs」, https://vercel.com/docs/cron-jobs/manage-cron-jobs — 확인 필요). 요금제별 크론 최소 간격도 확인 필요.

### 5-3. 폴링 설계
- 대상: **알림을 켠** 번호 중 끝나지 않은(FC 입고 전) 것만, 오래 안 본 순으로 한 번에 `batchLimit`(첫 판 40)건.
- 캐시: 마지막 조회에서 `cacheMinutes`(첫 판 20분) 안이면 부르지 않는다. 공개 조회도 같은 번호는 인스턴스 메모리에서 같은 시간 동안 다시 부르지 않는다.
- 하루 호출 수가 `dailyCallBudget` 에 닿으면 멈춘다(모자란 번호는 다음 회차). 그중 공개(비로그인) 조회는 `publicDailyBudget`(첫 판 150)까지만 — 비로그인 조회가 저장한 번호의 폴링 몫을 다 쓰지 못하게. 상한 검사와 호출 기록은 같은 잠금 안이 아니라 동시에 들어온 요청 몇 건은 넘을 수 있다(켜기 전 확인).
- 관세청 호출은 DB 트랜잭션 밖에서 한다(후보 고르기 · 번호마다 쓰기를 따로 짧게). 한 회차 시간 한도 45초(예약 경로 `maxDuration` 60초) — 닿으면 남은 번호는 다음 회차, 회차 기록은 멈춰도 남긴다.
- 켜짐이어도 **예시(데모) 조직 번호는 흉내로** 돌린다(지어낸 예시 번호를 관세청에 보내지 않는다).
- 기록: 회차마다 `unipass_poll_runs` 에 방식(실제/흉내/꺼짐)·본 번호·호출·실패·건너뜀. 운영 `/admin/tracking` 에서 본다. 번호·키·응답 원문은 이 기록에 남기지 않는다.
- `UNIPASS_ENABLED` 꺼짐이면: 예시(데모) 조직의 번호만 흉내 어댑터로 돌리고, **실제 조직의 번호는 건드리지 않는다**(가짜 단계가 실제 자료에 섞이지 않게).
- 단계가 바뀌면(폴링·지금 다시 조회·저장 때 조회 모두) 알림을 켠 사람에게 화면 안 알림 한 줄(「입항」「수리」「반출」, 여러 단계를 한 번에 건너면 한 줄에 모아). 알림 설정에서 「진행 상태」 화면 알림을 끈 사람·조직을 떠난 사람·버튼을 누른 사람은 뺀다. 밖으로는 보내지 않는다.

## 6. 개인정보 · 책임 · 위험

| 위험 | 대응 |
|---|---|
| **개인통관고유부호**(P + 숫자 12자리)를 번호 칸에 넣는 셀러 | 입력 검사에서 막는다 — 「개인통관고유부호는 넣지 마세요. 저장하지 않았습니다」. 서버도 같은 검사를 한 번 더 하고, 막은 값은 기록·로그에 남기지 않는다. 형식 출처: UNI-PASS 개인통관고유부호 안내(P로 시작하는 13자리 — 원문 확인 필요) |
| 응답에 수입자·화주 상호가 섞일 수 있음 | 저장하는 「원문 요약」은 처리구분·일시·장치장명 앞 60자만(반출입내용 `rlbrCn` 은 상호·사람 이름이 섞이는지 원문 확인 전까지 저장하지 않는다 — 확인 필요). 수입자·납세자 칸은 파서가 버린다 |
| 남의 B/L 을 넣어 남의 화물을 보는 일 | 관세청 공개 조회와 같은 범위(번호를 아는 사람은 이미 볼 수 있음)지만, 공개 화면은 저장하지 않고 분당 횟수를 묶는다. 저장한 번호는 그 조직만 본다(RLS) |
| 예상일을 약속으로 오해 | 화면마다 「예상 — 실측 분포로 셈한 참고치, 약속 아님」. 약속(8절 ①)은 스위치 꺼짐 |
| 관세청 자료의 늦음·오류 | 「관세청 UNI-PASS 기준 · 마지막 조회 시각」 표시. 물류사 기록과 다르면 둘 다 보인다 |
| 호출 한도 초과·차단 | 캐시·일일 한도·알림 켠 번호만. 429·5xx 는 지수 대기로 두 번까지만 다시 |
| 약관(상업 이용·재가공) 위반 | **확인 필요** — 확인 전에는 `UNIPASS_ENABLED` 를 켜지 않는다 |
| 실측 통계로 업체가 불리해짐 | 표본 기준 미만은 숨김, 표본 수를 늘 함께 적는다. 업체 답변 자리는 기존 후기 답변과 같은 방식으로 다음 단계 |
| 흉내 자료가 실제처럼 보임 | 흉내 결과엔 「예시 자료 — 실제 조회는 꺼져 있습니다」 띠, 데모는 기존 「예시 데이터」 띠 |

## 7. 단계 계획

1. **지금(5차)** — 흉내 어댑터로 화면·계산·기록·권한·데모까지. 실제 어댑터는 코드만(꺼짐).
2. **켜기 준비** — 5-2 의 1~3, 미리보기에서 셀러 두세 곳의 실제 번호로 확인(원문 칸 이름·처리구분 낱말 목록 확정 → 단계 규칙 고침).
3. **넓히기** — 선사 입항 예정(ETA) 자료, 쿠팡 WING 입고 기록과 FC 입고 자동 잇기, 관세 환율 API, 추천 점수에 실측 통관 소요 반영.
4. **새 사업(자리만)** — 8절.

## 9. 사람이 정할 일

> v2 전체 목록은 `docs/V2.md` 「5차에서 나온 사람이 정할 일」에 합쳤다(물류사 화면 실측 줄 · 반출입내용 저장 · 상한 잠금 세 줄을 거기서 더했다). 크론을 켜는 순서는 `docs/DEPLOY.md` 「통관 알리미 예약 작업(크론) 켜기」.

1. UNI-PASS 오픈API **원문 확인** — 연계가이드의 요청·응답 칸, 처리구분 낱말 전체 목록, 호출 한도, IP·도메인 조건, 키 발급 절차(즉시/승인).
2. 이용약관 — 상업 서비스에서 조회 결과를 보여 주고 **통계로 가공·공개**해도 되는지(업체별 실측 소요 공개 포함).
3. `UNIPASS_ENABLED` 를 켤지, 언제 — 1·2 가 끝난 뒤 미리보기에서 먼저.
4. 크론을 켤지·주기(5-2 의 4) — 호출 한도와 Vercel 요금제에 맞춰.
5. 표본 기준(`minSamples` 5)·기간(`windowDays` 90)·일일 한도(500)가 맞는지.
6. 공휴일 목록 확인 — 2026~2027 첫 판은 확인 필요 표시. 해마다 누가 새 판을 넣을지.
7. 업체 화면에 실측 통관 소요를 **공개**할지(업체 동의·답변권). 지금은 `tracker.partner_public_enabled` **꺼짐** — 예시 판만 보인다. 업체별 판은 FC도착 선적과 이은 번호만 쓴다(화주가 고른 물류사·관세사는 넣지 않음). 서로 다른 화주 조직 수 기준을 더할지도 여기서.
8. 도착일 약속(8절 ①) — 보상 범위·재원·보험, assure 와 함께.
9. 유료 모니터링(8절 ②) — 할지, 값, 결제(결제대행 제휴가 전제).
10. 저장한 번호·단계 기록의 보관 기간과 지우기(지우는 SQL 은 사람이 만든다).
