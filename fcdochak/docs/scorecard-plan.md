# 물류사 성적표 — 실측으로 고르는 견적 · 기획 (v2 6차 scorecard)

> 동관 김: 「단순한 통관조회화면은 아무 의미없다」.
> 목적은 **포워더·관세사의 전체 통관 상황을 실데이터로 모아, 물류사 알아보기·견적 비교의 지표로 쓰는 것**이다.
> 5차(`docs/tracker-plan.md`)에서 만든 관세청 조회·단계 기록·소요 통계는 이 성적표의 **원료 창구**로 물린다.

이 문서는 사람이 읽고 결정할 수 있게 쓴다. 확인하지 못한 사실은 「확인 필요」라고 적었다. 예시 업체·번호는 모두 가상이다.

---

## 1. 목적

### 1-1. 셀러에게 — 「싼 견적이 정말 싼가」

셀러가 물류사를 고를 때 보는 것은 지금 견적가뿐이다. 그런데 셀러가 실제로 잃는 돈은 **늦게 들어온 날 동안 못 판 매출**이다.
하루 40개 팔리고 개당 3,000원 남는 상품이면, 통관이 이틀 늦는 업체는 견적가가 20만 원 싸도 **실질적으로 4만 원 더 비싸지 않다** — 이틀 × 40개 × 3,000원 = 24만 원을 잃으므로 오히려 4만 원 비싸다.
그래서 비교 화면에 **실질 비용 = 견적가 + 예상 지연 비용**을 「평소」·「늦을 때」 두 값으로 싣는다(6절).

### 1-2. 물류사에게 — 「잘하는 업체가 가격 말고도 이길 수 있게」

통관이 빠르고 검사가 적고 들쭉날쭉하지 않은 업체는 지금 그것을 증명할 방법이 없다(자기 말뿐). 성적표는 **관세청 단계 기록으로 잰 값**이라 업체가 고칠 수 없다.
업체가 자기 화물번호를 **스스로 제출**하면 표본이 늘고, 셀러가 등록한 번호를 업체도 빠짐없이 냈는지(**제출률**)가 「실측 인증」이 된다 — 좋은 화물만 골라 내는 업체를 가려낸다.

### 1-3. 플랫폼에게 — 거래 밖에서도 쌓이는 비교 자료

5차의 모순 ③(거래 밖이라 실측 자료가 없다)을 푼다. 셀러 등록 · 물류사 제출 · 플랫폼 선적 세 길로 번호가 모이면, FC도착에서 거래하지 않은 화물도 업체 성적에 들어간다.

### 1-4. 넣지 않는 것

- 개인 직구(면세한도·합산과세·목록통관) — 5차와 같다.
- 다른 조회 서비스(7customs 등)를 긁거나 이름을 쓰는 것.
- 관세청이 공개하지 않는 업체별 전체 통계를 「있는 것처럼」 보이는 것(3절).

## 2. 비즈니스 모델 — 갈래와 고른 것

| 갈래 | 누가 돈을 내나 | 좋은 점 | 나쁜 점 | 고름 |
|---|---|---|---|---|
| A. 셀러 무료 → 자료·트래픽 | 없음(플랫폼 투자) | 번호가 가장 빨리 모인다. 공개 시장 지표가 셀러를 데려온다 | 바로 매출 없음 | **고름 — 기본** |
| B. 물류사 성적 리포트 구독 | 물류사 | 내 성적 대 평균·항구별 약점·경쟁 평균(이름 없이)을 원한다 | 무료 성적표와 차이가 있어야 한다 | **고름 — 2단계** (리포트 = 자세한 분포·주간 추이·이의 처리 우선) |
| C. 순위·인증을 파는 것 | 물류사 | 매출이 빠르다 | 성적표의 신뢰가 무너진다. 표시광고법 위험(7-2) | **고르지 않음** — 순위·「실측 인증」은 돈으로 못 산다. 광고는 따로 「광고」 표시(기존 광고 자리 규칙) |
| D. 실측 → 확정가·도착일 약속 위험 계산 | 셀러(보장료) 또는 물류사(수수료) | 5차 도착일 약속·v2 assure(확정가)와 이어진다 — 늦을 확률을 실측 p90 으로 셈 | 보상 책임·보험. 표본이 쌓여야 | **자리만** — `tracker.arrival_promise_enabled` 꺼짐 그대로. 성적표의 p50·p90 을 위험 계산의 입력으로 쓴다 |
| E. 시장 지표 리포트(항구·방식 추이, 이름 없음) | 무역·물류 회사, 언론 | 이름이 없어 법 위험이 작다 | UNI-PASS 자료를 가공·재배포해도 되는지 **약관 확인 필요**(7-3) | **공개 `/market/customs` 는 무료로만**. 유료 판매는 약관 확인 뒤 |

**고른 이유:** 성적표는 「돈을 낸 업체가 위에 온다」는 의심이 한 번이라도 들면 끝난다. 그래서 순위·인증은 무료이고 계산 방법을 공개하며, 돈은 **정보를 더 자세히 보는 것**(B)과 **위험을 대신 지는 것**(D)에서만 받는다.

## 3. 자료원과 그 한계 — 관세청 UNI-PASS

| 무엇 | 되는가 | 근거 |
|---|---|---|
| 화물 한 건 통관 진행정보(API001) | 된다 — 화물관리번호 또는 연도 + M B/L·H B/L | 5차 `docs/tracker-plan.md` 3절(원문 확인 필요) |
| 화물운송주선업자 목록·내역 | 된다고 한다 — **부호·상호**(내역은 주소 등) | 검색 요약: UNI-PASS 오픈API 30여 종 중 「화물운송주선업자 목록」이 부호·상호를 제공(원문 연계가이드는 이 환경에서 열지 못함 — **API 번호·주소·칸 이름 확인 필요**) |
| 관세사 목록 | **확인 필요** — 공개 오픈API 목록에서 찾지 못했다 | 그래서 관세사 기본 정보는 흉내 + 운영자가 넣는 표(`broker_profiles`) |
| **업체별 전체 통관 통계**(그 포워더가 이번 달 몇 건을 며칠 만에 통관했나) | **없다(공개 API 없음 — 확인 필요)** | 공개된 오픈API 목록·검색에서 찾지 못했다. 관세청 통계는 품목·국가별 수출입 실적(무역통계) 수준 |

그래서 업체별 실측은 **화물번호를 모아야** 생긴다. 번호가 들어오는 세 길:

| 번호 출처 | 누가 | 업체 귀속 | 믿음 |
|---|---|---|---|
| **플랫폼 선적** | 화주가 FC도착 선적에 B/L 을 이음 | 선적의 물류사(실제 거래) · 그 번호에 적은 관세사 | 가장 높다 |
| **셀러 등록** | 화주가 `/app/tracking` 에 번호를 넣고 물류사·관세사를 고름 | 화주가 고른 업체 | 중간 — 남의 B/L 로 경쟁 업체를 흔들 수 있다 → 교차 확인·이상치·이의 제기 |
| **물류사 제출** | 물류사가 `/partner/scorecard` 에 자기 화물번호를 붙여 넣음 | 제출한 업체 자신 | 중간 — 좋은 화물만 골라 낼 수 있다 → **제출률** |

모든 출처에서 **단계 시각은 관세청 기록**(5차 `cargo_track_events`, 사용자가 넣지 못함)이다. 출처는 「누가 번호를 알려 줬나」일 뿐, 숫자 자체는 누구도 손으로 넣지 않는다.

같은 화물은 한 번만 센다 — 관세청 화물관리번호(`cargo_no`), 없으면 (종류·번호·연도). 둘 이상의 출처가 같은 화물을 말하면 **교차 확인**으로 센다.

## 4. 지표 정의 — 식 · 단위 · 표본 기준 · 기간 · 출처

모든 지표는 (**물류사 또는 관세사**) × **항구** × **방식** 판과, 항구·방식을 묶은 「전체」 판으로 낸다. 전체 평균 판(업체 없음)도 같은 식으로 낸다.

| 지표 | 식 | 단위 | 비고 |
|---|---|---|---|
| **입항 → 수리 보통 / 늦으면** | 입항(없으면 하선) 첫 시각 → 수리(없으면 신고 뒤 반출) 첫 시각의 **한국 영업일** 수, p50 · p90(선형 보간) | 영업일 | 5차 `stageTimes`·`businessDaysBetween` 그대로 |
| **늦는 폭** | p90 − p50 | 영업일 | 작을수록 「안정적」 |
| **검사 비율** | 진행 단계에 **검사** 낱말(검사·검사대상 지정 등)이 있는 화물 ÷ 표본 | % | 처리구분 낱말 목록 원문 확인 전 **가정**(확인 필요). 검사 지정 자체는 업체 잘못이 아닐 수 있다 — 설명에 적는다 |
| **반입 → 반출** | 보세구역 반입 첫 시각 → (신고 뒤) 반출 첫 시각 | 영업일 p50 · p90 | 창고·관세사 처리 속도 |
| **반출 → FC 입고** | 반출 → 이은 선적의 9단계(FC 입고) | 영업일 p50 · p90 | 플랫폼 선적에서만 생긴다 |
| **제출률** | (셀러 등록 + 플랫폼 선적)으로 그 업체에 귀속된 화물 중, 그 업체도 **스스로 제출한** 화물의 비율 | % · (제출/등록 건수) | 물류사만. 등록이 0 이면 「셀 수 없음」 |
| **표본** | 기간 안에 수리가 끝난 화물 수(같은 화물 한 번) | 건 | `scorecard.rules.minSamples`(첫 판 5) 미만이면 **숨김** |
| **기간** | 수리일이 오늘 − `windowDays`(첫 판 180) + 1 ~ 오늘 | 날짜 | 칩에 「최근 180일」 |
| **출처 표시** | 표본을 번호 출처별로 센 수 + 교차 확인 수 | 건 | 칩에 「관세청 실측 · 셀러 12 · 물류사 9 · 선적 4」 |
| **전체 평균 대비** | 그 업체 p50 − 같은 항구·방식 전체 p50 | ±영업일 | 전체 판이 표본 미만이면 비교하지 않는다 |
| **추이** | 수리일 기준 주(월요일 시작)별 p50 · 건수, 최근 `trendWeeks`(12)주 | 영업일 | 한 주 표본이 2건 미만이면 그 주는 빈칸 |

**거래 지표(기존)** 는 따로 계산하지 않고 그대로 옆에 싣는다(출처 「FC도착 거래 기록」): 정시 입고율 · 견적 대비 청구 차이(`v_partner_metrics`) · 30일 FC 회송률 · 화주 후기. 견적 응답 속도는 요청 → 응찰 시각의 중앙값(시간)으로 새로 셈한다(`bids.created_at − quote_requests.created_at`).

**이상치:** 입항 → 수리가 `outlierDays`(첫 판 20영업일)를 넘는 화물은 분위수에서 빼고 따로 센다(보류·폐기·자료 오류일 수 있다). 운영 화면에서 번호를 본다.

**「실측 인증」**(돈으로 못 산다): 물류사 · 표본 ≥ `certifiedMinSamples`(10) · 등록 ≥ `certifiedMinSamples` · 제출률 ≥ `certifiedSubmissionBp`(80%). 조건이 깨지면 다음 계산에서 저절로 빠진다.

**계산 결과는 새 판으로 쌓는다**(`scorecard_snapshots`, 앞 판을 `supersedes_id` 로). 화면은 가장 최근 판만 본다. 예시(데모) 자료로 셈한 판과 실제 판은 섞지 않는다(5차와 같다).

## 5. 부정 방지

| 위험 | 막는 것 |
|---|---|
| 물류사가 좋은 화물만 제출 | **제출률**(셀러가 등록한 그 업체 화물을 업체도 냈는가). 인증 조건. 칩에 제출률을 함께 |
| 셀러가 남의 B/L 로 경쟁 업체를 흔듦 | 단계 시각은 관세청 기록뿐(손으로 못 넣음) · 같은 화물 한 번 · 출처별 수 공개 · 교차 확인 수 · 이상치 제외 · **이의 제기**(업체가 번호를 들어 이의 → 운영이 받아들이면 그 화물을 빼고 다시 셈) |
| 한 셀러가 한 업체 표본을 거의 다 채움 | 운영 화면에 「한 조직이 표본의 절반 이상」 경고(자료 품질). 자동 제외는 하지 않음 — 사람이 정할 일 |
| 같은 번호를 여러 번 | 화물관리번호로 한 번 · 제출은 (업체·종류·번호·연도) 하나 |
| 운영자가 숫자를 고침 | 계산 결과 표에 사용자·운영자 쓰기 권한이 없다(서버 신뢰 경로만). 이의 처리·부호 연결은 쌓기만/새 판 — 감사 가능 |

## 6. 실질 비용 — 견적가 + 예상 지연 비용

```
예상 지연일(평소)  = max(0, 그 업체 p50 − 비교 기준)
예상 지연일(늦을 때) = max(0, 그 업체 p90 − 비교 기준)
비교 기준        = 후보 중 가장 빠른 p50 (없으면 같은 항구·방식 전체 중앙값)
지연 비용        = 하루 판매량 × 개당 마진 × 예상 지연일   (원 단위 사사오입, 마진이 0 이하면 0)
실질 비용        = 견적가 + 지연 비용
```

- 하루 판매량·개당 마진: 비교에 고른 SKU 가 **판매 분석**(쿠팡 판매 기록)과 이어져 있으면 그 값(최근 판매 속도 · 개당 이익). 없으면 **셀러가 넣는 값**. 둘 다 없으면 **지연 일수만** 보인다(금액을 지어내지 않는다).
- 「평소」는 p50, 「늦을 때」는 p90 — 「늦을 때」는 10번 중 1번쯤 그보다 더 늦는다는 뜻(확률 표시).
- 영업일 기준이라 주말을 끼면 실제 판매 손실은 더 클 수 있다(화면에 적는다). 순수 함수 `src/lib/money/realcost.ts` + 시험.
- 표본이 모자란 업체는 실질 비용을 셈하지 않고 「실측 없음」.

## 7. 법적 위험 — 왜 업체 이름 공개 스위치가 꺼져 있나

`scorecard.public_named` = **꺼짐**. 이름 붙은 성적은 **로그인한 화주 · 그 업체 자신 · 운영자**만 본다. 공개 면(`/market/customs`, 비로그인 `/partners`)은 이름 없는 집계만.

### 7-1. 명예훼손·신용훼손

- 정보통신망법 제70조(사실 적시 명예훼손) · 형법 제307조·제313조(신용훼손). 사실이어도 「비방할 목적」이 있으면 처벌될 수 있고, 공공의 이익이면 위법성이 조각될 수 있다(형법 제310조) — **조문 원문·판례 대조 필요**.
- 줄이는 것: 관세청 기록에 근거한 **사실**만 · 계산 방법 공개 · 표본 기준 미만 숨김 · 출처 표시 · 업체의 **답변·이의 제기** 자리 · 로그인 사용자 한정.

### 7-2. 표시·광고의 공정화에 관한 법률

- 순위·「인증」 표시가 돈을 받고 매겨지면 기만적 표시·광고가 될 수 있다(법 제3조 — 원문 확인 필요). 공정위 「추천·보증 등에 관한 표시·광고 심사지침」도 경제적 이해관계 공개를 요구한다(확인 필요).
- 줄이는 것: 순위·인증 무료 · 광고는 「광고」 칩(기존 광고 자리 규칙) · 특수관계 업체는 기존처럼 「특수관계 공개」.

### 7-3. UNI-PASS 약관·공공데이터

- 조회 결과를 모아 **가공·재공개·유료 판매**해도 되는지 UNI-PASS 오픈API 이용약관 · 공공데이터법(제3조 이용 활성화, 제17조 제공 대상) 해석 **확인 필요**. 공개 시장 지표는 무료·이름 없음으로만 시작한다.
- 번호는 셀러·업체의 거래 정보다 — 공개 면에 개별 번호를 싣지 않는다(5차와 같다).

### 7-4. 업체 동의

- 5차 결정(`tracker.partner_public_enabled` 꺼짐)을 이어받는다. 업체에 알리고(입점 약관에 성적표 조항) 답변권을 주기 전에는 공개하지 않는다.

## 8. 절차 · 준비물

### 8-1. 셀러
1. `/app/tracking` 에 B/L 을 넣는다(「내 화물 등록 → 성적표에 보탬」). 물류사·관세사를 고르면 그 업체 성적에 들어간다.
2. FC도착 선적과 이으면 「플랫폼 선적」 출처가 된다.
3. `/app/compare` 에서 성적 칩·실질 비용을 본다. 판매 분석을 이으면 금액이 자동으로.

### 8-2. 물류사
1. `/partner/scorecard` 에 화물번호를 한 줄에 하나씩 붙여 넣는다(최대 200줄). 개인통관고유부호는 거절.
2. 내 성적 대 평균 · 제출률 · 인증 조건을 본다.
3. 틀렸다고 보면 번호·지표를 들어 이의 제기 → 운영이 받거나 돌려보낸다(기록은 남는다).

### 8-3. 운영(켜기 전 준비물)
1. 관세청 연계가이드 원문으로 API001·화물운송주선업자 API 칸 이름 확인(3절).
2. `/admin/scorecard` 에서 업체 ↔ 관세청 **화물운송주선업자 부호** 연결(흉내 목록으로 먼저 연습, 켜면 실제 목록). 연결은 새 판.
3. 관세사 기본 정보 입력(등록번호·주 세관) — 흉내 첫 판을 고쳐 새 판으로.
4. 이의 처리 · 자료 품질(출처별 수 · 교차 확인 · 이상치 · 한 조직 쏠림) 확인.
5. 「성적표 다시 셈」(예약은 없다 — `/api/cron/unipass` 가 제출 번호 조회를 함께 돈다, 예약 켜기는 5차와 같이 사람이).
6. 법무 검토(7절) 뒤에만 `scorecard.public_named` 을 켠다.

### 8-4. 스위치 · 설정

| 이름 | 첫 값 | 뜻 |
|---|---|---|
| `UNIPASS_ENABLED`(환경변수, 5차) | 꺼짐 | 켜기 전에는 관세청을 부르지 않는다 — 부호 목록도 흉내 |
| `scorecard.rules` | minSamples 5 · windowDays 180 · certifiedMinSamples 10 · certifiedSubmissionBp 8000 · outlierDays 20 · trendWeeks 12 · 출처 셋 모두 · example true | 표본 기준·기간·인증 |
| `scorecard.public_named` | **false** | 이름 붙은 성적 공개 |

## 10. 사람이 정할 일

1. **이름 공개**(`scorecard.public_named`) — 법무 검토(명예훼손·표시광고·약관) 뒤에만. 켤 때 업체 사전 고지·답변권 기간.
2. **셀러 등록 출처를 업체 성적에 넣을지** — 5차 소요 통계는 뺐고(DECISIONS), 성적표는 넣되 출처별로 따로 센다. 조작이 보이면 `scorecard.rules.sources.seller` 를 끈다.
3. **이상치 기준**(20영업일)과 제외 여부 — 보류·폐기 화물이 업체 탓인지.
4. **인증 조건**(표본 10 · 제출률 80%)과 이름(「실측 인증」).
5. **한 조직 쏠림**을 자동으로 뺄지.
6. **검사 비율**을 싣을지 — 검사 지정은 무작위·품목 탓일 수 있다(업체 탓이 아님). 지금은 「참고」로 싣는다.
7. **물류사 리포트 구독 가격**·내용.
8. **관세사 정보 출처** — 공개 API 가 없으면 관세사회 명부 등(확인 필요) 사용 허락.
9. **UNI-PASS 약관**의 가공·재배포·상업 이용.
10. 물류사가 제출한 번호의 화주 정보(수입자) — 우리는 번호·단계만 저장한다. 수입자 동의가 필요한지(개인정보·영업비밀) 확인 필요.
