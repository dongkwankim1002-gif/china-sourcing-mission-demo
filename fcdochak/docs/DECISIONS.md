# 판단 기록 — 한 줄에 하나

- 작업 가지는 세션이 지정한 `claude/fcdochak-phase-1-0n4xlc` 하나로 하고, 단계는 커밋으로 나눴다(`fcdochak-<단계>` 가지 여러 개 대신). PR 은 `fcdochak` 으로.
- `fcdochak` 기준 가지는 `main` 에서 새로 떴다. `main` 과 저장소 뿌리 파일은 건드리지 않았다(뿌리에 도구 설정이 없어 예외가 필요 없었다).
- 표는 `public` 이 아니라 `fcd` 스키마에 둔다 — Supabase PostgREST 에 기본 노출되지 않게.
- Supabase 의 `anon`/`authenticated` 대신 자체 역할 `fcd_user`·`fcd_public` 로 `set local role` 해서 RLS 를 받는다. 앱은 서버에서만 DB 에 붙는다.
- 로그인 확인은 Supabase Auth(있으면)·로컬 scrypt(없으면), 세션은 자체 서명 쿠키(`fcd_session`, HS256). 브라우저에 Supabase 키를 두지 않는다.
- `fcd.profiles.id` 는 `auth.users` 를 FK 로 참조하지 않는다 — 로컬 PGlite 와 같은 스키마로 돌리고, 데모 걷어내기를 한 SQL 로 끝내려고.
- 환경변수가 없으면 PGlite 로 끝까지 돈다(시험·미리보기·로컬). 두 드라이버의 값 모양(date·timestamptz·int8)을 같게 맞췄다.
- 마이그레이션은 SQL 파일을 빌드 때 TS 로 묶어(`migrations.generated.ts`) 서버리스에서도 파일 없이 올린다. 시험이 둘이 같은지 본다.
- 거래 기록 표(요금표·응찰·청구·설정·관세율·등급)는 UPDATE 권한 자체가 없다. 정정은 `supersedes_id` 로 새 판을 쌓는다. 상태 칸만 바뀌는 표(요청·예외·광고 등)는 따로 둔다.
- 삭제 요청 처리 = 업체 상태를 `deleted` 로 바꾸기(공개 면에서 사라짐). 실제로 지우는 SQL 은 만들지 않았다.
- 참조표(거점·항구·FC·구간·화물 성격)는 코드가 원본이라 `db:migrate` 때 upsert 한다. 설정·관세율은 키가 없을 때만 첫 판을 넣고, 운영자가 쌓은 판은 덮지 않는다.
- 돈 계산은 `src/lib/money` 의 순수 함수만. BigInt 로 자릿수를 고정하고 반올림은 사사오입, 세금은 원 단위 버림.
- 성사 수수료 기준 = 물류비 합계 − 관세사 보수, 관세·부가세 제외(관세사법 제3조 제2·3항). 시험으로 고정.
- 관세·부가세는 「참고 추정」으로만 보이고 목록통관은 다루지 않는다.
- 업체가 맡지 않는 구간은 플랫폼 참고치(설정 `reference_lines`)로 채워 합계를 보이되, 점선 무늬로 구분하고 확정 합계에서는 뺀다.
- 비교 목록은 운송(freight) 구간을 포함한 요금표만 올린다 — 운송이 없는 요금표는 같은 조건 비교가 안 된다.
- 비로그인 계산기는 「공개 가격」으로 표시한 요금표만 쓰고, 금액 대신 구간 비중(천분율)만 돌려준다.
- 추천 점수 = 정시 30 · 청구 편차 25 · FC 회송 25 · 가격 확정도 20. 실측이 없으면 중립 0.5. 광고·특수관계는 점수에 넣지 않는다.
- 광고는 한 구간·기간에 한 자리만(서버에서 겹침 검사), 목록 맨 위에 「광고」 표시.
- 「FC 입고 준비 인증」 기준(60건·3.5%)은 설정 표에서 읽는다. 쿠팡 상표는 쓰지 않는다.
- 공개 정보 업체(미등록)는 이름·지역·업종·출처만. 가격·소개·사진·개인 연락처를 싣지 않는다.
- 물류사는 경쟁사의 비공개 요금표를 볼 수 없다(`fcd.i_am_shipper()` 로 화주에게만 비교용 공개) — 시험 있음.
